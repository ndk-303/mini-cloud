Cloud Computing 101: IaaS, PaaS, SaaS

TỔNG QUAN VỀ CÁC MÔ HÌNH DỊCH VỤ ĐIỆN TOÁN ĐÁM MÂY VÀ LIÊN HỆ KIẾN TRÚC THỰC TẾ

HÌNH 2.1: HẠ TẦNG ĐIỆN TOÁN ĐÁM MÂY KẾT NỐI TOÀN CẦU VỚI CÁC MÔ HÌNH DỊCH VỤ ĐA DẠNG

Điện toán đám mây (Cloud Computing) đã trở thành trụ cột của hạ tầng công nghệ số toàn cầu. Việc hiểu rõ sự phân định trách nhiệm giữa ba mô hình IaaS, PaaS và SaaS là chìa khóa để thiết kế hệ thống tối ưu về cả chi phí lẫn hiệu năng.

1. Phân cấp 3 mô hình dịch vụ đám mây

Mỗi mô hình dịch vụ phản ánh mức độ quản lý mà nhà cung cấp đảm nhiệm so với người sử dụng:

  • IaaS (Infrastructure as a Service): Nhà cung cấp quản lý phần cứng, ảo hóa, mạng và trung tâm dữ liệu. Khách hàng chịu trách nhiệm cài đặt hệ điều hành, runtime và ứng dụng (Ví dụ: AWS EC2, GCP Compute Engine).
  • PaaS (Platform as a Service): Nhà cung cấp quản lý cả hệ điều hành, runtime và môi trường thực thi. Lập trình viên chỉ cần tải lên mã nguồn ứng dụng (Ví dụ: AWS Elastic Beanstalk, Google Cloud Run).
  • SaaS (Software as a Service): Phần mềm hoàn chỉnh được cung cấp qua Internet. Người dùng chỉ cần đăng nhập và sử dụng mà không cần quan tâm đến hạ tầng bên dưới (Ví dụ: Google Workspace, Microsoft 365).

2. Ánh xạ các thành phần trong MiniCloud

Trong đồ án môn học, hệ thống MiniCloud mô phỏng trực quan các dịch vụ đám mây công nghiệp tương ứng:

  • Nginx Proxy Server: Tương đương AWS Application Load Balancer (ALB) hoặc API Gateway.
  • SeaweedFS Server: Tương đương AWS S3 hoặc Google Cloud Storage (Object Storage lưu trữ file bài viết và avatar).
  • MariaDB Server: Tương đương AWS RDS (Relational Database Service lưu trữ dữ liệu sinh viên và blog).
  • Keycloak Server: Tương đương AWS Cognito hoặc GCP Identity Platform (IAM & SSO).
  • Bind9 DNS Server: Tương đương AWS Route 53 (Private Hosted Zone cloud.local).

3. Lời kết

Hiểu sâu sắc các tầng dịch vụ này giúp sinh viên không chỉ sử dụng thành thạo các công cụ đám mây có sẵn mà còn có tư duy kiến trúc để giải quyết các bài toán kỹ thuật phức tạp trong doanh nghiệp.
